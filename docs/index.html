detection engineering · autonomous-agent tradecraft

The intruder is a language model.

A pack of detections tuned to how an autonomous LLM agent operates a host, shipped with the telemetry that proves each one fires.

Repository ATT&CK coverage

A model API on an allowlist is not a detection.

The interesting signal isn't that a host talked to a model API. It's that the same session talked to a model and acted on the host between calls, again and again, at a tempo no human types at and no script pauses for. agentdetect keys on that rhythm, not on any one payload.

Every detection ships with two traces: an attack sample that must fire it and a benign near-miss that must stay silent. CI replays both through a real Splunk on every push. A rule that matches everything fails the benign half; a rule that matches nothing fails the attack half.

The behavioral flagships

Signals that survive when the adversary vendors the SDK, spoofs the user agent, or rotates infrastructure, because they measure how an agent operates, not what it downloads.

agent-loop-interleavenative Splunk

Model call, host action, model call, host action, repeated in one session. The signature of a tool-use loop, and the one thing a benign AI feature never does: it calls the model; it doesn't then run cat /etc/passwd. T1102T1071.001

agent-command-cadencenative Splunk

Non-interactive command bursts spaced by inference-latency gaps: faster and more regular than a human, far slower than a shell script. T1059

agent-retry-stormnative Splunk

The same tool re-run with a tweak within seconds of each failure, over and over. Machine self-correction, not a human giving up. T1059

recon-breadth-burstnative Splunk

One session sweeping six or more distinct discovery categories inside two minutes, because a model already knows every path worth checking. T1082T1057T1033

sensitive-read-llm-exfilnative Splunk

A credential read followed by a large POST to a model API. Exfiltration wearing a prompt as a costume. T1567T1041

Telemetry, not science fiction

Every fixture is written in one small schema modeling the two events any Linux EDR already emits: process creation and network connection. Nothing here needs a feed you don't collect. The novelty is in what the rules look for.

detections.yaml (single source of truth) │ ┌───────────┴───────────┐ rules/**/*.yml rules/**/*.spl (Sigma) (native Splunk) │ │ Sigma → SPL run as-is └───────────┬───────────┘ Splunk (CI service) index a fixture's events, run the search │ attack trace → must fire benign trace → must stay silent

The fixtures don't have to be hand-written

The emulate command hands an objective to a real Claude agent, gives it one run_shell tool wired into a throwaway container stocked with synthetic honeypot data, and records what it actually does (every command, its exit code, its timing) into the same schema. The attacker isn't scripted; a model decides what to run, and its real operating rhythm becomes the trace.

uv sync --extra emulate
export ANTHROPIC_API_KEY=...
agentdetect emulate recon-and-loot \
  --out fixtures/emulated.alert.json

Runs only against the sandbox, needs your own key, never runs in CI.

agentdetect is a detection-engineering portfolio project by Jacob Hess. Ten detections across the agent kill chain, each tagged to MITRE ATT&CK and proven against a real Splunk in CI.

Field-match anchors (traffic to a model API, an SDK user agent, a credential read, an IMDS hit) are shipped too, and deliberately labelled as the brittle, spoofable half, to make the case for the behavioral rules beside them.
